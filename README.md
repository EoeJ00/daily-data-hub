# 日报数据中枢（第一版）

一个无前端依赖的本地 Web 程序，用于按业务日期完成渠道日报归集，以及“甲方日报 → 投手日报 → 总表”的配对搬运。

## 已实现

- 一次粘贴多个 Google 表格链接，支持 `名称 | 链接` 格式。
- 自动去重、启停和移除本地工作簿配置。
- 默认排除 `充值明细`、`总表（所有渠道）`、`总表`。
- 以其他符合字段结构的页签名称作为渠道号。
- 业务日期默认取前一天，也可以选择历史日期补跑。
- 源值为空、公式空字符串或纯空格时跳过，不写 `0`、不清空目标值。
- 数字 `0` 作为有效值正常处理。
- 总表目标为空时才进入待写入；相同值跳过；不同值标记冲突且不覆盖。
- 支持预览、正式写入和运行日志。
- 情景二支持配置多组“甲方表 + 自己日报表”，各配对独立读取和运行。
- 情景二兼容完整链名、短渠道编号和末尾投手代号，并以配对内唯一渠道编号为主键。
- 情景二先写投手日报，重新读取确认后再写总表。

## 启动

需要 Node.js 20 或更高版本：

```powershell
npm start
```

然后访问 [http://localhost:4173](http://localhost:4173)。

也可以直接双击项目目录中的 `start-miulx.bat`。它会自动检查 Google 服务账号文件、避免重复启动已有服务，并打开本地控制台。

启动器默认读取：

```text
C:\Program Files\safe\miulx-daily-hub.json
```

如果所在网络需要 HTTP 代理访问 Google API，可在双击启动器前，在同一个 PowerShell 窗口设置代理（端口以你的代理软件实际配置为准）：

```powershell
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
$env:HTTP_PROXY = $env:HTTPS_PROXY
.\start-miulx.bat
```

启动器检测到 `HTTP_PROXY` 或 `HTTPS_PROXY` 后，会自动让 Node.js 使用环境代理。这里需要填写 HTTP 代理地址；如果只有 SOCKS 代理，请使用代理软件提供的 HTTP 端口。

也可以直接执行：

```powershell
node server.mjs
```

## Google 服务账号配置

程序使用 Google Sheets API。创建 Google Cloud 服务账号、启用 Google Sheets API，并把需要处理的每个工作簿共享给服务账号邮箱。

推荐用凭据文件启动：

```powershell
$env:GOOGLE_SERVICE_ACCOUNT_FILE = "D:\secure\google-service-account.json"
npm start
```

也支持把完整凭据 JSON 放入 `GOOGLE_SERVICE_ACCOUNT_JSON` 环境变量。

凭据文件不要放入项目目录，也不要提交到版本控制。

## 第一版表格约定

渠道页签会在前 12 行中查找表头。默认字段别名：

- 日期：`日期`、`时间`、`date`
- 消耗：`消耗`、`广告消耗`、`当日消耗`、`spend`
- 回流消耗：`回流消耗`、`回流`、`return spend`

目标总表支持以下常见表头：

- 单层：`渠道号`、`渠道号回流`
- 单层：`渠道号消耗`、`渠道号回流消耗`
- 双层：上层为渠道号，下层为 `消耗`、`回流消耗`
- 相邻列：渠道号后一列标题为 `回流` 或 `回流消耗`

当前日报表的实际映射规则：

- 渠道页签名称仅作为显示名称和投手记录，例如 `11yXxZgy02(SUKI)`。
- 写入总表时会自动去掉末尾括号及其中的投手代号，使用 `11yXxZgy02` 匹配总表列；页面仍保留完整页签名称，便于追溯投手。
- 本示例总表第一行是 `日期`、渠道号、相邻的 `回流` 列，系统会把渠道号列识别为“消耗”，其右侧 `回流` 列识别为“回流消耗”。
- Google Sheets 中标记为“隐藏”的页签不会读取、不会计入渠道数量，也不会产生运行记录。

如果实际总表采用合并单元格或其他结构，需要在下一版根据真实表结构补充映射配置。

## 安全边界

- 正式执行会重新读取最新数据。
- 只写入预览状态为“待写入”的空白目标单元格。
- 不自动覆盖冲突值。
- 删除工作簿配置只影响本地配置，不会删除 Google 表格。
- `data/state.json` 保存本地配置和最近 50 次运行记录，已加入 `.gitignore`。

## 情景二表格约定

- 甲方日报可以重复出现每日表头；日期只出现在首行时，会在当前日报块内向下继承。
- 支持 Google 日期序列、`YYYY-MM-DD`、`M.D`、`M/D` 和 `M月D日`。
- 渠道格式支持 `MMY-XIONG-SS1-34`、`34(ROY)`、`MMY-XIONG-SS1-34（ROY）`。
- 自己的投手页签从名称提取渠道编号，例如 `34(ROY)`；同一编号匹配多个页签时停止写入。
- 投手日报通过“日期、渠道号、花费、回流”表头定位列，第一版只处理已经存在的日期行。
- 总表按渠道编号与相邻回流列匹配；源值为空时按指标跳过，数字 `0` 正常处理。
- 隐藏页签忽略，目标已有不同值时保留原值并记录冲突。

## 一键启动（Windows）

日常使用可直接双击 `start-miulx-hidden.vbs`。它会在后台启动服务、自动打开 `http://localhost:4173`，不会显示 PowerShell 或 Node 控制台。

启动器默认使用 `http://127.0.0.1:7890` HTTP 代理；如果代理软件端口不同，请编辑同目录的 `start-miulx-hidden.cmd`。需要查看错误信息时，再使用 `start-miulx.bat`。

## 工作流

- `情景一 / 渠道日报归集`：使用日报字段识别、总表渠道映射和安全写入流程。
- `情景二 / 配对日报记录`：在每组配对内部识别甲方日报块和渠道编号，先安全写入投手日报，再复核并写入自己的总表。
